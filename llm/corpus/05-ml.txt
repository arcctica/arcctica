machine learning is the idea that a program can improve by looking at examples instead of following rules that someone wrote by hand. you show it many cases, it makes a guess for each one, and it adjusts itself to make better guesses. a spam filter learns from thousands of mails, and a language model learns from billions of sentences.

a neural network is a long chain of simple steps. each step multiplies a list of numbers by a table of numbers, adds the results, and applies a small bend such as setting all negative values to zero. one step can do very little, but many steps stacked on top of each other can describe very complicated patterns. the tables of numbers are called weights or parameters, and learning means finding good values for them.

to learn, the network needs a way to measure how wrong it is. this measure is called the loss. for text, the loss is the average surprise of the model at the true next character. if the model gave the right character a high probability, the loss is small. if the model was sure about a different character, the loss is large. a model that guesses at random among thirty characters has a loss of about three and a half.

the question is then how to change the weights to make the loss smaller. gradient descent answers it. for every weight, you compute how much the loss would change if the weight moved a little, and you move each weight a small step in the direction that lowers the loss. the size of the step is the learning rate. a rate that is too big makes the loss jump around, and a rate that is too small makes learning very slow.

the gradient of every weight is found with backpropagation. the network is a chain of simple steps, and the rule for the slope of a chain is to multiply the slopes of its links. so you start at the loss and walk backwards through the network, and at each step you pass the slope to the step before it. this takes about as much work as running the network forwards, no matter how many weights there are.

a good optimizer does more than take plain steps. adam keeps a running average of the recent slopes, which smooths out the noise, and a running average of the squared slopes, which tells it how steep each weight usually is. it uses both to give every weight a step of a sensible size. the learning rate also usually starts small, grows quickly, and then slowly shrinks, so that the model settles down at the end.

a model can learn the training examples too well. when it has many weights and little data, it starts to remember the examples instead of finding the pattern behind them, and it fails on anything new. this is called overfitting. the loss on the training text keeps falling, while the loss on text that the model has never seen starts to rise. the only honest way to know is to keep some text aside and test on it.

every example has to be turned into numbers first. for text, the first step is to cut it into tokens. a token can be a character, a word or a piece of a word. each token gets a number, and each number is mapped to a list of values called an embedding. at the start the embeddings are random, but during training the model moves them around so that tokens used in similar ways end up close together.

the order of the tokens matters, and a plain network would not know it. so the model adds a second list of numbers that depends on the position, and it adds it to the embedding. now the same letter at the start of a word and at the end of a word looks different to the model, and it can learn that some letters tend to follow others.

attention is the idea that made modern language models possible. for each token the model asks a question, which is a list of numbers called the query. every earlier token offers a key, and the model compares the query with every key. a strong match means that the earlier token is important for this question. the matches are turned into weights that add up to one, and the model takes a weighted mix of the values of the earlier tokens.

a model has to be careful not to look into the future when it is trained to predict the next token. if it could see the answer, it would just copy it. so the attention is masked: each position may look only at itself and at the positions before it. this is what makes the model causal, and it is also what lets us use it to generate text one token at a time.

one attention head is a single way of looking. a model uses several heads in parallel, and each head can learn a different habit. one head may look at the previous character, another may look for the last time the same letter appeared, and a third may keep track of where the current word began. you can see these habits by drawing the weights of every head, and sometimes the pattern is surprisingly clear.

to generate text, the model reads what has been written so far and outputs a probability for each possible next token. you then pick one. if you always pick the most likely token, the text becomes dull and starts to repeat. if you pick at random in proportion to the probabilities, the text is more varied. a number called the temperature controls this: a low temperature plays it safe, and a high temperature takes risks and makes more mistakes.

large models are trained on far more text and have billions of weights, and they show abilities that small models do not have. but they still do the same thing: they predict the next token. they can say something false with complete confidence, because the training rewards text that sounds right and not text that is right. making a model that knows what it does not know is still one of the open problems.

understanding what happens inside a model is its own field of research. one can look at which inputs a part of the network responds to, remove a part and see what breaks, or follow a piece of information from the start to the end. the dream is to read a network the way one reads a program, and to be able to say why it gave an answer, and not just what the answer was.

good research is careful about small things. you write down the question before the experiment, you change one thing at a time, you keep the settings and the random seed so that others can repeat it, and you report the runs that failed as well as the runs that worked. a result that nobody else can reproduce is not yet a result, and a clean chart that hides the bad runs is worse than no chart.

a company is a way to put a good idea in front of many people. it starts with a problem that a real person has, and the first version is built to test the idea and not to be perfect. then you show it to people early, you listen to what they say, and you change it. the teams that win are often not the ones with the best first idea, but the ones that learn the fastest from what they see.

whether the path leads to a laboratory or to a company, the foundation is the same. you learn the mathematics, you write the code by yourself until the machine stops being a mystery, and you build things that other people can use and check. the tools will change every year, but a person who understands how the pieces work can pick up any new tool within a week.
